# 🎮 شب بازی — ربات بازی تلگرام با مینی‌اپ، فقط روی Telegram Serverless

ربات بازی چندزبانه (فارسی، انگلیسی، فرانسوی، روسی) با یک **مینی‌اپ** کامل که همه‌چیزش — کد سرور، دیتابیس،
وبهوک و فایل‌های مینی‌اپ — روی **سرورلس خود تلگرام** ([Telegram Serverless](https://core.telegram.org/bots/serverless))
اجرا می‌شود. بدون VPS و بدون سرور جدا.

ربات: [@Wanger_gamebot](https://t.me/Wanger_gamebot) · مینی‌اپ: `https://app8740157051.tgcloud.ai/`

## 🧭 دعوت دوست — بدون هیچ تنظیمی در BotFather کار می‌کند

1. **فرستادن دعوت** (یکی از این دو راه):
   - در هر چتی یوزرنیم ربات را تایپ کنید (`@Wanger_gamebot`) و یک بازی را انتخاب کنید؛ یا
   - در مینی‌اپ روی یک بازی بزنید ← «دعوت دوستان» ← «ارسال در یک چت» (یا «کپی لینک»).
2. **دوستتان** روی دکمه‌ی «▶️ بازی» می‌زند:
   - اگر ربات «مینی‌اپ اصلی» داشته باشد، بازی مستقیم باز می‌شود (یک لمس).
   - اگر نداشته باشد (وضعیت فعلی)، چت ربات باز می‌شود ← **START** ← ربات دکمه‌ی «▶️ بازی» می‌دهد که همان اتاق را باز می‌کند.
   ربات خودش از تلگرام می‌پرسد کدام حالت برقرار است و لینک درست را می‌سازد.
3. صندلی **فرستنده‌ی دعوت** از لحظه‌ی ارسال رزرو است. وقتی دوستش وارد اتاق شود، ربات در پی‌وی به فرستنده پیام می‌دهد
   «فلانی منتظر توست» با دکمه‌ای که مستقیم همان اتاق را باز می‌کند. بازی وقتی شروع می‌شود که همه اتاق را باز کرده باشند.
   (ربات فقط به کسی می‌تواند پیام بدهد که قبلاً آن را استارت کرده باشد.)
4. رزروی که تا ۳ دقیقه باز نشود آزاد می‌شود؛ هر کس حاضر است می‌تواند با ربات شروع کند.

## 🏗 معماری (کوتاه)

- **قوانین بازی‌ها** ماژول‌های خالص در `tgcloud/lib/games/` هستند که هم سرور و هم مینی‌اپ از آن‌ها استفاده می‌کنند.
- **سرور مرجع است:** مینی‌اپ فقط «حرکت موردنظر» را می‌فرستد؛ سرور بررسی می‌کند و وضعیت را با **شماره‌ی نسخه** ذخیره
  می‌کند (دو حرکت هم‌زمان هر دو ثبت نمی‌شوند).
- **همگام‌سازی:** مینی‌اپ هر ~۱٫۱ ثانیه وقتی نوبت دیگری است `getState(room, since)` را صدا می‌زند (در نوبت خودت، لابی و
  بیکاری کندتر؛ وقتی مینی‌اپ پنهان است اصلاً)؛ اگر چیزی عوض نشده باشد جواب فقط `{ same: true }` است.
- **زمان‌بند ندارد:** سرورلس تلگرام cron و تایمر ندارد، پس همه‌چیز در درخواست بعدی بررسی می‌شود: تایمر نوبت (با تمام شدن
  وقت، سرور به‌جای بازیکن حرکت می‌کند و ۳ بار پشت‌سرهم یعنی باخت یا جایگزینی با ربات)، حرکت ربات‌ها، منقضی شدن اتاق‌ها
  و پیشرفت پیام همگانی.
- **محدودیت‌های اندازه‌گیری‌شده‌ی پلتفرم:** حدود ۳ ثانیه CPU و ۳۰ ثانیه زمان برای هر فراخوانی؛ بدون تراکنش (هر تغییر = یک
  دستور SQL)؛ بدون WebSocket. طراحی بر همین اساس است.
- **عضویت اجباری** برای ربات، همه‌ی endpointها و حالت اینلاین؛ نتیجه‌ی موفق ۸ دقیقه کش می‌شود.
- **گزارش مینی‌اپ:** مینی‌اپ هر بار باز شدن و هر خطای سمت کاربر (مثلاً رد شدن پنجره‌ی اشتراک‌گذاری) را به سرور گزارش
  می‌دهد؛ مالک در پنل ← «🧾 گزارش مینی‌اپ» می‌بیند.

## 🚀 راه‌اندازی

پیش‌نیاز: Node.js ۲۲+، رباتی که در BotFather **Serverless** و **CLI Access** آن روشن است و **inline mode** دارد (`/setinline`).

```bash
cd game_bot
npm install
mkdir -p .tgcloud              # مهم: وگرنه CLI ممکن است پروژه‌ی ریشه‌ی مخزن را بردارد
npx tgcloud login              # یا متغیر محیطی TGCLOUD_TOKEN
npm run deploy                 # build مینی‌اپ + push کد و فایل‌ها + migrate جدول‌ها
```

`push` آدرس مینی‌اپ را چاپ می‌کند؛ آن را در `tgcloud/lib/config.js` در `APP_URL` بگذارید (با `/` آخر) و دوباره
`npm run deploy` کنید.

> پشت پروکسی HTTPS دستورهای CLI را با `NODE_USE_ENV_PROXY=1` اجرا کنید. همیشه قبل از push، build کنید
> (`npm run deploy` این کار را می‌کند).

## ⚙️ تنظیمات BotFather

**لازم:** فقط روشن بودن inline mode (`/setinline`) و ادمین بودن ربات در کانال‌های عضویت اجباری.

ربات این‌ها را **خودش** تنظیم می‌کند (از طریق Bot API، با اولین پیام بعد از استقرار): دکمه‌ی منو («بازی») و فهرست
دستورها به چهار زبان.

**اختیاری — برای تجربه‌ی بهتر:**

| تنظیم | نتیجه |
|---|---|
| Bot Settings ← **Configure Mini App** ← Main Mini App با URL = `APP_URL` | دعوت‌ها با **یک لمس** مستقیم بازی را باز می‌کنند (بدون رفتن به چت ربات)، و جدول رتبه‌ی «همین چت» فعال می‌شود. ربات این را حداکثر تا ۱۰ دقیقه بعد خودش تشخیص می‌دهد |
| `/setinlinefeedback` ← Enabled | پیام دعوت بعد از شروع و پایان بازی با نتیجه ویرایش می‌شود |

### تست دستی در تلگرام (با دو حساب)

1. حساب ۱: در چت با حساب ۲ بنویسید `@Wanger_gamebot` ← یک بازی را بفرستید.
2. حساب ۲: «▶️ بازی» ← (اگر چت ربات باز شد) START ← «▶️ بازی». باید لابی همان اتاق را ببیند با «منتظر … که بازی را باز کند».
3. حساب ۱: پیام ربات «… منتظر توست» ← «▶️ بازی». بازی برای هر دو شروع می‌شود.
4. اگر چیزی کار نکرد: `/admin` ← «🧾 گزارش مینی‌اپ» نشان می‌دهد روی گوشی چه شده است.

## ➕ افزودن یک بازی جدید

1. **قوانین:** `tgcloud/lib/games/<name>.js` — خالص، بدون `sdk`:
   `SEATS, TURN_SEC, create(opts, rng), turn(state), act(state, seat, action, rng) → { state } | { error },
   auto(state, seat, rng), outcome(state), rematch(state, rng), view(state, seat)` و رویدادها با `logEvent`.
   اختیاری: `waiting(state)` (حرکت هم‌زمان)، `MIN_SEATS` (شروع با نفرات کمتر)، `LEAVER_BECOMES_BOT`.
2. **ثبت:** `MODS` در `tgcloud/lib/rooms.js`؛ `GAMES`، `ROOM_GAMES`، `GAME_SEATS` و یک حرف در `PAYLOAD_LETTER` در
   `tgcloud/lib/config.js`؛ آیکون در `GAME_ICONS` (`tgcloud/lib/i18n/index.js`).
3. **متن‌ها:** `game_<name>`، `desc_<name>` و متن‌های بازی در هر چهار فایل `tgcloud/lib/i18n/*.js` (بدون `&`، `<`، `>`).
4. **رابط:** `app/games/<Name>.tsx` (props: `room`, `move`, `busy`) و ثبت در `BOARDS` در `app/screens/Room.tsx`؛ تصویر SVG
   در `app/art.js` و `npm run thumbs`.
5. **تست:** تست قوانین در `test/unit/`، یک سناریو در `test/e2e.mjs` و `test/ui.mjs`؛ بعد `npm test` و `npm run deploy`.
