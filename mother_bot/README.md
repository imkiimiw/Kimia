# 🤖 ربات مادر Wanger — همه‌ی ربات‌ها در یک‌جا

ربات مادر همه‌ی ربات‌های Wanger را می‌شناسد و یک‌جا مدیریتشان می‌کند. مثل بقیه‌ی ربات‌های این مخزن فقط روی
**سرورلس خود تلگرام** ([Telegram Serverless](https://core.telegram.org/bots/serverless)) اجرا می‌شود؛ کد، دیتابیس
و وبهوک همه داخل تلگرام است.

- **برای کاربر:** راهنما و پاسخ‌گوی سؤال‌ها، دسترسی سریع به ربات‌ها، گزارش خطا با بررسی خودکار، تابلوی وضعیت،
  خبرهای اختیاری، باشگاه مشتریان و تاریخچه‌ی استفاده.
- **برای تیم:** پنل یکپارچه، تیکت‌ها، اختلال‌ها، سلامت ربات‌ها، حالت تعمیر/محدود، بن سراسری، عضویت اجباری مرکزی،
  پیام همگانی، آمار و کمپین‌های تخفیف.

## ✨ قابلیت‌ها

### برای کاربرها

| قابلیت | چطور |
|---|---|
| 💬 **دستیار** | هر چیزی بنویسید: «دانلودر کدوم رباته؟»، «چطور نجوا بفرستم؟»، اسم یک ربات، یا «ربات موزیک جواب نمیده». ربات مناسب، قابلیت و طرز استفاده‌اش را می‌گوید، با دکمه‌ی باز کردن ربات. اگر جوابش را نداشت: «✉️ سؤالم را برای تیم بفرست». |
| 🤖 **دسترسی سریع** | `/bots`: دسته‌ها (دانلود، موسیقی، سرگرمی، …)، **تازه‌ترین ربات‌ها**، همه‌ی ربات‌ها؛ صفحه‌ی هر ربات با معرفی، زبان‌ها، راهنمای قابلیت‌ها، سؤالات رایج و لینک. لینک مستقیم صفحه‌ی ربات: `t.me/<mother>?start=b_music` |
| 🛠 **گزارش خطا** | `/report` ← ربات ← توضیح (متن یا اسکرین‌شات). ربات مادر بررسی می‌کند (پایین‌تر): اگر واقعاً خطا بود تیم توسعه خبردار می‌شود و کاربر وقتی درست شد خبر می‌گیرد؛ اگر مشکل از سمت کاربر بود راهنمایی می‌گیرد («✅ حل شد / ❌ حل نشد»). |
| 📶 **وضعیت ربات‌ها** | `/status`: 🟢 فعال · 🟡 اختلال · 🔧 تعمیر · 🔴 قطع · ⏳ محدود، با توضیح و زمان تقریبی پایان؛ دکمه‌ی «🔔 وقتی درست شد خبرم کن». |
| 🔔 **اطلاع‌رسانی (اختیاری)** | `/news`: خبر کدام ربات‌ها و چه نوع خبری (ربات جدید، آپدیت و قابلیت/زبان تازه، اختلال و تعمیرات، اطلاعیه‌ی مهم). در صفحه‌ی هر ربات: «🔔 خبرهای این ربات را بفرست». بدون روشن کردن، هیچ خبری نمی‌آید. |
| 🎁 **باشگاه مشتریان** | `/club`: عضویت اختیاری؛ امتیاز از فعالیت روزانه در ربات‌ها، دعوت دوستان و خرید اشتراک؛ سطح 🥉🥈🥇💎؛ کد تخفیف ماهانه و مناسبتی (کد شخصی یک‌بارمصرف یا کد مشترک)؛ «🎟 کدهای من». |
| 👤 **پروفایل و تاریخچه** | `/profile`: ربات‌های محبوب (بیشترین استفاده)، تاریخچه‌ی هر ربات (تعداد و آخرین بار)، ربات‌هایی که هنوز امتحان نکرده، گزارش‌های من. |
| 🚨 **گزارش کاربر مزاحم** | پیامی از او فوروارد کنید (یا آیدی) + توضیح؛ برای بررسی تیم می‌رود. |

### برای تیم (`/admin`)

| بخش | چه می‌کند |
|---|---|
| 🤖 ربات‌ها | فهرست با وضعیت، سلامت، توکن و اتصال هاب. صفحه‌ی هر ربات: آمار، 📶 وضعیت (با توضیح و مدت)، 🎛 دسترسی (🔧 بسته برای تعمیر / ⏳ محدود / ✅ آزاد)، 🩺 سلامت، ✏️ ویرایش اطلاعات (معرفی، قابلیت‌ها، سؤالات رایج، رفع مشکل، کلمات جستجو…)، 🔑 توکن، 🔄 همگام‌سازی هاب، 🆕 اعلام ربات جدید، ➕ ربات جدید (اول مخفی). |
| 🎫 تیکت‌ها | باز / پاسخ داده شد / راهنمایی شد / حل شد. ✉️ پاسخ (به کاربر می‌رسد و او می‌تواند جواب بدهد)، ✅ حل شد، 🚨 تأیید باگ (اختلال). |
| 🟡 اختلال‌ها | باز و حل‌شده؛ ثبت دستی؛ «✅ حل شد» به همه‌ی منتظران خبر می‌دهد. |
| 🩺 سلامت | وبهوک هر ربات (با توکن)، خطاهای گزارش‌شده، هشدار سکوت؛ «بررسی همه الان». |
| 📊 آمار | امروز: فعال، جدید، استفاده، خطا، بلاک برای هر ربات؛ ۷ روز اخیر هر ربات؛ کاربران و اعضای باشگاه. |
| 👤 کاربران / 🗂 صف سوءاستفاده | پرونده‌ی کامل کاربر (ربات‌هایی که استفاده کرده، گزارش‌ها، تیکت‌ها، بن‌ها، اخطارها، یادداشت)؛ ⚠️ اخطار، ⛔️ بن ۱ ساعت/۱ روز/۷ روز/دائم در همه‌ی ربات‌ها یا یک ربات، ✅ رفع بن، 📝 یادداشت. |
| 📰 خبر و اطلاعیه | برای مشترکان یک ربات یا «اخبار کلی»، با نوع خبر. |
| 📢 عضویت اجباری (مالک) | کانال‌های سراسری و اختصاصی هر ربات؛ با توکن، ادمین بودن هر ربات در کانال چک می‌شود. |
| 📣 پیام همگانی (مالک) | به کاربران ربات مادر و/یا کاربران ربات‌های انتخابی (از طرف خود هر ربات، با توکنش)؛ هر نفر یک بار؛ متن، عکس، ویدیو، فایل، گیف، ویس، آهنگ. |
| 🎁 باشگاه (مالک) | کمپین‌ها (درصد، مدت، ربات‌ها، حداقل سطح، شخصی/مشترک با سقف)، 📣 اعلام به اعضا، ⛔️ توقف، 📅 هدیه‌ی ماهانه‌ی خودکار. |
| ⚙️ تنظیمات (مالک) | کانال هاب، چت لاگ تیم، اعضای تیم، هوش مصنوعی، خبر خودکار وضعیت، پاک کردن هاب. |

- **مالک فقط آیدی عددی `5557901897`** است (`tgcloud/lib/config.js`). اعضای تیم (مالک اضافه می‌کند) تیکت‌ها،
  اختلال‌ها، کاربران، وضعیت/دسترسی ربات‌ها، سلامت، آمار و خبرها را دارند؛ بقیه فقط برای مالک است.
- هشدارها، خطاها، تیکت‌ها و گزارش‌های سوءاستفاده به **چت لاگ تیم** (یک کانال یا گروه خصوصی) می‌روند؛ اگر تنظیم نشده
  باشد به پی‌وی اعضای تیم.

## 🔎 بررسی خودکار گزارش خطا

به این ترتیب:

1. ربات در حالت **🔧 تعمیر** است → «مشکل از شما نیست؛ وقتی باز شد خبرتان می‌کنیم».
2. تیم وضعیت اختلال گذاشته یا **اختلال بازی** هست → «این مشکل را می‌دانیم»؛ گزارش به اختلال وصل می‌شود.
3. **نشانه‌ی واقعی بودن**: ۳ کاربر مختلف در یک ساعت، یا ۵ خطا از خود ربات (از طریق هاب)، یا خطای وبهوک همین الان
   (با توکن) → «مشکل از ربات است»؛ اختلال ثبت و تیم توسعه خبردار می‌شود.
4. «رفع مشکل»های همان ربات (یا هوش مصنوعی، اگر کلید دارد) می‌گوید مشکل از سمت کاربر است → راهنمایی + «حل شد / حل نشد».
5. در غیر این صورت → تیکت برای تیم؛ جواب در همان چت می‌آید.

## 🔌 ارتباط با ربات‌ها: کانال هاب

سرورلس تلگرام آدرس عمومی برای دریافت پیام از ربات‌های دیگر ندارد، پس ربات‌ها در یک **کانال خصوصی** (هاب) با هم حرف
می‌زنند: هر ربات فرزند با فایل [`client/mother-client.js`](client/mother-client.js) آمار، خطا و بلاک‌ها را پست
می‌کند و تنظیمات (تعمیر/محدود، عضویت اجباری)، بن‌ها و کدهای تخفیف را از ربات مادر می‌خواند.
راهنمای کامل وصل کردن هر ربات: **[client/README.md](client/README.md)**.

بدون وصل کردن هم هر ربات در ربات مادر صفحه، راهنما، دستیار، تابلوی وضعیت (دستی) و گزارش خطا دارد؛ با **توکن**،
سلامت وبهوک و پیام همگانی از طرف خود ربات هم اضافه می‌شود.

## 🚀 راه‌اندازی

پیش‌نیاز: یک ربات تازه برای ربات مادر در [@BotFather](https://t.me/BotFather) ← ربات ← **Serverless** ← روشن.

با Node.js ۱۸ به بالا، **داخل همین پوشه**:

```bash
cd mother_bot
npm install
mkdir -p .tgcloud              # مهم: وگرنه CLI ممکن است پروژه‌ی ریشه‌ی مخزن را بردارد
npx tgcloud login              # یا متغیر TGCLOUD_TOKEN (BotFather ← ربات ← Serverless ← CLI Access)
npx tgcloud status             # فقط ماژول‌های همین پوشه
npx tgcloud push
npx tgcloud migrate --safe     # ساخت جدول‌ها
npx tgcloud webhook            # باید in sync باشد: message, callback_query, channel_post, poll, my_chat_member
```

> پشت پروکسی HTTPS (مثلاً نشست ابری Claude Code) دستورهای CLI را با `NODE_USE_ENV_PROXY=1` اجرا کنید.

بعد در تلگرام:

1. به ربات مادر `/start` بدهید (فهرست اولیه‌ی ۱۰ ربات Wanger خودکار ثبت می‌شود)، بعد `/setup` (منوی دستورها و
   توضیح ربات).
2. **کانال هاب**: یک کانال خصوصی بسازید، ربات مادر را ادمین کنید (ارسال و حذف پیام)، و در `/admin` ← ⚙️ تنظیمات ←
   📡 یک پست از آن فوروارد کنید.
3. **چت لاگ تیم** (اختیاری): ⚙️ ← 📋؛ کانال: فوروارد یک پست؛ گروه: در گروه `/setlog`.
4. **اطلاعات ربات‌ها** را کامل کنید (🤖 ← ربات ← ✏️): یوزرنیم‌هایی که خالی‌اند، قابلیت‌ها، سؤالات رایج و «رفع مشکل»؛
   دستیار و بررسی خطا از همین‌ها جواب می‌دهند.
5. **ربات‌ها را یکی‌یکی وصل کنید**: [client/README.md](client/README.md).
6. (اختیاری) **توکن** هر ربات (🔑)، **هوش مصنوعی** با `/aikey KEY` (کلید رایگان Gemini از aistudio.google.com؛ پیام
   فوراً پاک می‌شود)، **هدیه‌ی ماهانه** (🎁 ← 📅).
7. (اختیاری) **ساعت بیرونی**: secret مخزن `MOTHER_TGCLOUD_TOKEN` را بگذارید تا
   `.github/workflows/mother-tick.yml` هر ۳۰ دقیقه کارهای زمان‌دار را اجرا کند (بدون آن هم این کارها با هر پیام/پست
   هاب انجام می‌شوند).

## 🔒 امنیت و محدودیت‌ها

- **توکن ربات‌ها** فقط در دیتابیس ربات مادر ذخیره می‌شود (سرورلس متغیر محیطی ندارد)؛ پیامی که توکن در آن است فوراً
  پاک می‌شود، توکن دیگر نمایش داده نمی‌شود و در هیچ trace یا لاگی نمی‌آید. هر کس به حساب مالک دسترسی داشته باشد به
  آن‌ها هم دسترسی دارد؛ توکن فقط برای ربات‌هایی بگذارید که سلامت وبهوک یا پیام همگانی از طرف خودشان را لازم دارید.
- **هاب** فقط باید مالک و ربات‌ها را به‌عنوان ادمین داشته باشد؛ ربات مادر فقط پست‌های همان کانال و فقط برای
  ربات‌های فهرست را می‌پذیرد.
- **هوش مصنوعی** اختیاری است؛ فقط متن سؤال (نه نام یا آیدی) به Gemini می‌رود و جواب‌ها فقط از روی اطلاعاتی است که
  تیم برای ربات‌ها نوشته. سقف روزانه برای کل ربات و هر کاربر دارد؛ بدون آن، جستجوی کلمه‌ای جواب می‌دهد.
- **زمان‌بند ندارد**: پایان تعمیر، بررسی سلامت و هدیه‌ی ماهانه با اولین پیام یا پست هاب بعد از موعدشان انجام می‌شوند؛
  پیام همگانی با بیدار کردن خودش (poll در کانال هاب) تا آخر می‌رود. خود ربات فرزند پایان تعمیر را خودش هم رعایت می‌کند.
- خود ربات مادر کسی را با عضویت اجباری قفل نمی‌کند تا همه بتوانند سؤال بپرسند و خطا گزارش بدهند.

```bash
npm test     # بررسی‌های ایستا + ۳۸ سناریوی سرتاسری روی شبیه‌ساز محلی sdk
```

سناریوها یک ربات فرزند واقعی (همین `client/mother-client.js`) را هم شبیه‌سازی می‌کنند: پست‌های هاب بین دو طرف
رد و بدل می‌شوند، و Bot API ربات‌های فرزند و Gemini با `fetchHooks` جواب داده می‌شوند.
