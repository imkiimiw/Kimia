# 🔌 وصل کردن یک ربات به ربات مادر

هر ربات Wanger (روی Telegram Serverless) با یک فایل به ربات مادر وصل می‌شود: `mother-client.js`.
بعد از وصل شدن:

- آمار استفاده، کاربران جدید، خطاها و کاربرانی که ربات را بلاک کرده‌اند به ربات مادر می‌رسد (تاریخچه‌ی کاربران،
  داشبورد آمار، لاگ خطا، بررسی سلامت)؛
- حالت **تعمیر** و **محدود** و **بن سراسری** که تیم در ربات مادر می‌زند، در خود ربات اعمال می‌شود؛
- کانال‌های **عضویت اجباری مرکزی** و **کدهای تخفیف** باشگاه مشتریان به ربات می‌رسد.

> پیشنهاد: ربات‌ها را **یکی‌یکی** وصل کنید؛ هر بار یکی را وصل و امتحان کنید، بعد سراغ بعدی بروید.

## ارتباط چطور برقرار می‌شود؟

سرورلس تلگرام آدرس HTTP عمومی برای دریافت پیام از ربات‌های دیگر ندارد (endpointها فقط تماس تأییدشده‌ی مینی‌اپ را
می‌پذیرند). برای همین ربات‌ها از یک **کانال خصوصی** به اسم «هاب» با هم حرف می‌زنند:

```
ربات فرزند ── پست «#wg1 {…}» در کانال هاب ──▶ ربات مادر (channel_post)
ربات مادر  ── پست «#wg1 {…}» در کانال هاب ──▶ ربات فرزند (channel_post)
```

ربات مادر پیام‌هایی را که خوانده پاک می‌کند تا کانال شلوغ نشود. هر کس بتواند در هاب پست بگذارد می‌تواند از طرف ربات‌ها
حرف بزند، پس **فقط مالک و ربات‌ها** ادمین هاب باشند.

## مراحل (برای هر ربات)

1. **کلید ربات** را در ربات مادر ببینید: `/admin` ← 🤖 ربات‌ها. کلید هر ربات کنار اسمش است (مثلاً `music`، `media`،
   `whisper`). اگر ربات در فهرست نیست: ➕ ربات جدید.
2. **ربات را در کانال هاب ادمین کنید** (فقط اجازه‌ی ارسال پیام کافی است).
3. **فایل را کپی کنید**: `mother_bot/client/mother-client.js` ← `<ربات>/tgcloud/lib/mother.js` و دو خط بالای آن را
   پر کنید:
   ```js
   export const BOT_KEY = 'music';           // کلید همین ربات در ربات مادر
   export const HUB_CHAT = -1001234567890;   // آیدی کانال هاب (ربات مادر بعد از تنظیم هاب نشانش می‌دهد)
   ```
4. **جدول را به `schema.js` اضافه کنید** و بعد `npx tgcloud migrate --safe`:
   ```js
   // کانال هاب ربات مادر: پیکربندی، بن‌ها، کدهای تخفیف و آمارهای در صف (tgcloud/lib/mother.js)
   export const motherHub = table('mother_hub', {
     key: text('key').primaryKey(),
     value: text('value'),
   });
   ```
5. **`handlers/channel_post.js`** (اگر ربات این هندلر را ندارد بسازید؛ پلتفرم وبهوک را خودش به‌روز می‌کند):
   ```js
   import { onHubPost } from '../lib/mother.js';

   export default async function (post) {
     if (await onHubPost(post)) return { hub: true };
     // … کار قبلی ربات با پست‌های کانال (اگر داشت)
     return {};
   }
   ```
6. **قبل از جواب دادن به کاربر** (در router، بعد از تشخیص ادمین بودن):
   ```js
   import { gate, track, reportError } from './mother.js';

   const g = await gate(from.id, { admin: isAdmin });
   if (!g.ok) {
     await api.sendMessage({ chat_id: chat.id, text: g.text });   // بن، تعمیر یا محدود
     return;
   }
   // … کار عادی ربات …
   await track(from.id, isNewUser);   // isNewUser: اولین بار است که این کاربر را می‌بیند
   ```
   و در `catch`ها:
   ```js
   } catch (err) {
     await reportError('handlers/message', err);
     throw err; // یا هر کاری که قبلاً می‌کرد
   }
   ```
7. **اختیاری‌ها**:
   - هر جا ارسال به کاربر با `403` شکست خورد: `await reportBlocked(userId)`.
   - تشخیص اسپم خود ربات: `await reportAbuse(userId, 'flood', 'توضیح')` — در صف سوءاستفاده‌ی ربات مادر می‌آید.
   - بعد از پرداخت موفق (مثلاً `successful_payment` با استارز):
     `await reportPurchase(userId, amount, 'XTR', codeUsed)` — امتیاز باشگاه و ثبت مصرف کد تخفیف.
   - کد تخفیف: `const promo = await checkPromo(code, userId)` ← `{ p: درصد, until, uid }` یا `null`.
   - عضویت اجباری مرکزی: `await requiredChannels()` ← `[{ id, u, t, inv }]`؛ این فهرست را کنار کانال‌های خود ربات
     در بررسی عضویتش بگذارید (ربات باید در آن کانال‌ها ادمین باشد).
   - آمار کل کاربران خود ربات در داشبورد مادر: گاهی `await flush({ stats: { users: total } })`.
8. `npx tgcloud push`، بعد در ربات مادر صفحه‌ی ربات ← **🔄 همگام‌سازی هاب**. در همان صفحه باید «📡 آخرین گزارش هاب»
   و «تأیید ربات: v…» به‌روز شود.
9. (اختیاری) **توکن** ربات را در صفحه‌اش (🔑 توکن) ثبت کنید تا ربات مادر سلامت وبهوک را بررسی کند و از طرف این ربات
   به کاربرانش پیام همگانی و اخطار بفرستد.

## چه چیزی کجا می‌رود (پروتکل)

هر پست: `#wg1 ` و یک JSON: `{ "b": فرستنده, "k": نوع, "to": گیرنده, "t": زمان یونیکس, "d": داده }`.

| از فرزند به مادر | داده |
|---|---|
| `hello` | `{ v }` — پیکربندی ندارم؛ ربات مادر پیکربندی، بن‌ها و کدها را دوباره می‌فرستد |
| `hb` | `{ v, users? }` — هر ۱۰ دقیقه (هنگام فعالیت) |
| `use` | `{ u: [[userId, تعداد, جدید؟], …] }` — حداکثر هر ۲ دقیقه یک بار |
| `err` | `{ e: [[امضا, متن, تعداد], …] }` |
| `blk` | `{ u: [userId, …] }` |
| `abuse` | `{ u, r: دلیل, d: توضیح }` |
| `buy` | `{ u, amt, cur, code? }` |
| `ack` | `{ v }` — نسخه‌ی پیکربندی اعمال‌شده |

| از مادر به فرزند | داده |
|---|---|
| `cfg` | `{ v, mode: off/slow/closed, msg, until, slow, join: [{ id, u, t, inv }] }` |
| `ban` / `unban` | `{ u: [userId, …], until, s }` — `until: 0` یعنی دائم |
| `promo` / `promos` / `promo_off` | `{ c: کد, p: درصد, bots, until, uid, max }` / `{ l: [promo, …] }` / `{ c }` یا `{ cs: [کدها] }` |

چیزی از این فایل هیچ‌وقت خطا به کد ربات پرتاب نمی‌کند؛ اگر هاب در دسترس نباشد فقط ربات مادر کمتر خبر دارد.
با `HUB_CHAT = 0` همه‌ی تابع‌ها بی‌اثرند، پس می‌شود فایل را زودتر اضافه و بعداً روشن کرد.

## ربات‌هایی که روی سرورلس نیستند (Wanger News)

Wanger News (پایتون روی GitHub Actions) فعلاً گزارش‌هایش را با HTTPS به یک آدرس می‌فرستد
(`adapters/mother.py`)، که ربات مادر روی سرورلس نمی‌تواند دریافت کند. راه وصل کردنش: یک adapter کوچک که همان
رویدادها را با توکن ربات خودش به‌صورت پست `#wg1` در کانال هاب بفرستد (ربات خبر باید ادمین هاب باشد)؛ بعد از آن
**هشدار سکوت** (ویرایش ← هشدار سکوت، مثلاً ۹۰ دقیقه) هم برایش کار می‌کند. تا آن موقع Wanger News در ربات مادر
صفحه‌ی معرفی و راهنما و وضعیت دستی (📶 وضعیت) دارد.
