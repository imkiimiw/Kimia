# Wanger News

پلتفرم جمع‌آوری، راستی‌آزمایی و انتشار خبر (اول تلگرام). خبرها را از منابع معتبر می‌گیرد، تکراری‌ها را حذف
می‌کند، دسته‌بندی و اولویت‌بندی می‌کند و با ذکر منبع در کانال تلگرام منتشر می‌کند. علاوه بر RSS، یک
**کانال منبع تلگرام** هم دارد: هر پستی آن‌جا بگذارید، اگر قبلاً منتشر نشده باشد در کانال مقصد کپی می‌شود.

**وضعیت: فاز ۵** — قوانین ویرایشی، اصلاحیه، آمار و هزینه، پیشنهاد اعتبار منابع و API داشبورد؛ از فاز ۴: خبر فوری 🔴، هشدار زودهنگام «موضوع در حال رشد»، لینک به خبرهای مرتبط، روند خبر در
به‌روزرسانی‌ها و خلاصهٔ روز (ساعت ۲۱). از فاز ۳: گزارش‌های منابع مختلف دربارهٔ یک رویداد کنار هم قرار می‌گیرند (Story)، منابع مستقل شمرده
می‌شوند، تناقض‌ها گزارش می‌شوند و خبر تازه دربارهٔ موضوع منتشرشده به‌صورت «به‌روزرسانی» (Reply) می‌آید.
خبرها با هوش مصنوعی (Gemini) به فارسی خلاصه، راستی‌آزمایی و با تأیید ادمین منتشر می‌شوند. پیش‌فرض انتشار همچنان **کانال تست** است تا خودتان با `/settings target main` عوض کنید. برنامه و وضعیت: [PLAN.md](PLAN.md) · معماری و
تصمیم‌ها: [ARCHITECTURE.md](ARCHITECTURE.md) · آخرین تست زندهٔ منابع: [docs/SOURCES_CHECK.md](docs/SOURCES_CHECK.md).

این پوشه یک پروژهٔ Python مستقل است؛ بقیهٔ پوشه‌های مخزن ربات‌های دیگرند و دست نخورده‌اند.

## فاز ۶: گسترش

| بخش | توضیح |
|---|---|
| گزارش هفتگی | هر جمعه ۲۰:۰۰ تهران در کانال: خبرهای هفته به عدد، مهم‌ترین رویدادها با لینک، رویدادهای در جریان، موضوع‌های پرگزارش، منابع پرسهم. فقط از خبرهای منتشرشده، بدون متن تازهٔ AI. پیش‌نمایش: `/weekly` یا پنل ← 🗓 |
| جستجو | `/search بانک مرکزی`: در خبرهای منتشرشده؛ اول با کلمه‌ها، بعد با معنا (≈) |
| نسخه‌ها (شخصی‌سازی) | کانال‌های اضافه که از پست‌های کانال اصلی فقط آنچه را می‌خواهید می‌گیرند: دسته‌ها، حداقل اهمیت، فقط فوری، با یا بدون به‌روزرسانی. پنل ← 🌐 نسخه‌ها، یا `/edition add @کانال en` و `/edition set شناسه categories=economy min=60` |
| انگلیسی | نسخه با زبان `en`: ترجمهٔ همان خلاصهٔ تأییدشده، با بررسی عدد و نام؛ اگر بررسی رد شود، آن خبر در نسخهٔ انگلیسی منتشر نمی‌شود |
| بات مادر | با Secretهای `WANGER_NEWS_MOTHER_URL` و `WANGER_NEWS_MOTHER_SECRET`، هر اجرا و رویدادهای مهم با امضای HMAC به بات مادر گزارش می‌شوند. قرارداد پیام: ARCHITECTURE ← ADR-058 |
| داشبورد وب | گزینهٔ B: `python -m wanger_news api` ← `https://سرور/dashboard` (با همان `WANGER_NEWS_API_TOKEN`) |
| API موبایل | گزینهٔ B: `/api/v1/feed`، `/api/v1/stories/{id}`، `/api/v1/search?q=`، `/api/v1/categories`، `/api/v1/weekly`؛ با توکن جدا `WANGER_NEWS_MOBILE_API_TOKEN` که فقط خبرهای منتشرشده را می‌خواند |

## فاز ۳: هوشمندی خبری

| بخش | توضیح |
|---|---|
| Story (یک رویداد) | هر خبر با embedding (Gemini) با رویدادهای ۷۲ ساعت اخیر مقایسه می‌شود (شباهت معنایی + نام‌های مشترک + زمان). گزارش‌های یک رویداد یک پست می‌گیرند، نه چند پست |
| چندمنبعی | یک خلاصه از همهٔ منابع رویداد (حداکثر ۵)؛ ربات ۱۵ دقیقه صبر می‌کند تا منابع جمع شوند (خبر فوری صبر نمی‌کند). پست: «📰 منابع: A، B» |
| منابع مستقل | کپی یک خبرگزاری در چند سایت، یا سایت‌های یک مالک، **یک منبع** حساب می‌شوند |
| ادعا و شاهد | هر ادعا با منبع‌هایی که آن را گفته‌اند و جملهٔ عینی هر منبع؛ وضعیت: تأییدشده (۲ منبع مستقل) / احتمال بالا / تأییدنشده / متناقض / ردشده |
| تناقض | اگر منابع با هم نمی‌خوانند، ربات برنده انتخاب نمی‌کند: «⚖️ گزارش‌ها دربارهٔ … متفاوت است؛ A …، در حالی که B ….» — و چنین خبری همیشه اول به بررسی شما می‌رسد |
| به‌روزرسانی | اگر بعد از انتشار، منبع مستقل تازه‌ای **اطلاعات جدید** بیاورد، پست کوتاه «🔄 به‌روزرسانی» به‌صورت Reply زیر پست قبلی منتشر می‌شود؛ اگر چیز تازه‌ای نداشته باشد فقط به‌عنوان تأیید شمرده می‌شود |
| کانال منبع | پست شما (اگر قبلاً منتشر نشده باشد) بدون آیدی‌های منبع و با امضای کانال مقصد فرستاده می‌شود و به رویدادش وصل می‌شود؛ پستی که دستی در کانال انتشار بگذارید هم همان رویداد را «منتشرشده» می‌کند |

> آستانه‌های تشخیص «همان رویداد» هنوز روی embedding واقعی کالیبره نشده‌اند (کلید Gemini در محیط توسعه نبود)؛
> روزهای اول کارت‌های بررسی را ببینید و در صورت نیاز `story:` را در `config/pipeline.yaml` تنظیم کنید.

## فاز ۲: هوش مصنوعی و بررسی انسانی

| بخش | توضیح |
|---|---|
| خلاصهٔ فارسی | Gemini برای هر خبر عنوان، ۱ تا ۳ (خبر مهم: ۳ تا ۶) پاراگراف، نکته‌های کلیدی، نام‌ها با املای اصلی در پرانتز و نقل‌قول‌ها در «» می‌سازد. متن کامل مقاله هرگز ترجمه یا بازنشر نمی‌شود |
| ضد توهم (Hallucination guard) | لایهٔ ۱ بدون AI: هر عدد و تاریخ، هر نام لاتین و هر نقل‌قول باید در متن منبع باشد و هر ادعا شاهدِ کلمه‌به‌کلمه از منبع داشته باشد. لایهٔ ۲: یک بررسی دوم با AI. اشکال ← یک بار بازنویسی ← باز اشکال ← بررسی انسانی. **هرگز خودکار منتشر نمی‌شود** |
| امتیازها | اهمیت (۰ تا ۱۰۰) و اطمینان (۰ تا ۱۰۰) با جزئیات قابل‌توضیح؛ خبر تک‌منبع حداکثر «گزارش اولیه» |
| حالت انتشار | برای هر دسته: خودکار (auto)، نیمه‌خودکار (semi، پیش‌فرض) یا دستی (manual). موضوعات حساس (جنگ، مرگ، کودتا، انتخابات، رهبران و …) در هر حالتی به بررسی انسانی می‌روند |
| کارت بررسی | در پی‌وی مالک (و ادمین‌ها) با پیش‌نمایش دقیق پست و دکمه‌های ✅ تأیید، 📤 انتشار فوری، ✏️ ویرایش (متن تازه را Reply کنید)، ❌ رد. چون ربات سرور ندارد، دکمه‌ها در اجرای بعدی (چند دقیقه) اثر می‌کنند |
| بودجه | سقف فراخوانی AI در هر اجرا و هر روز (`config/pipeline.yaml` ← `ai`)؛ اگر سهمیه تمام شود خبرها برای اجرای بعدی می‌مانند. هر فراخوانی با توکن و هزینه ثبت می‌شود |
| دستورها | `/news /pending /approve 12 /publish 12 /reject 12 /settings` (`/settings mode technology auto`، `/settings target main`) |

## راه‌اندازی رایگان (GitHub Actions + Neon) — قدم‌به‌قدم

کانال‌های این ربات: تست [@testtt2334q](https://t.me/testtt2334q) · اصلی (مقصد) [@maghsad98](https://t.me/maghsad98)
· منبع [@manbaeeeee](https://t.me/manbaeeeee). این نام‌ها در workflow به‌عنوان پیش‌فرض گذاشته شده‌اند و از داخل
ربات (`/panel` ← کانال‌ها) هم عوض می‌شوند؛ لازم نیست Variable بسازید.

**۱. ربات در کانال‌ها** — در هر سه کانال: تنظیمات کانال ← Administrators ← Add Admin ← ربات را پیدا کنید.
در کانال تست و کانال اصلی اجازهٔ **Post Messages** روشن باشد. در کانال منبع ادمین بودن کافی است. برای هشتگ
اسم پست‌گذار، در کانال منبع **Sign Messages** (امضای پیام‌ها) را روشن کنید.

**۲. دیتابیس رایگان Neon**
1. به [neon.tech](https://neon.tech) بروید ← **Sign up** (با حساب گوگل یا GitHub ساده‌تر است).
2. ساخت پروژه: یک نام (مثلاً `wanger-news`)، نسخهٔ Postgres پیش‌فرض، و Region نزدیک (مثلاً Frankfurt) ← **Create project**.
3. در داشبورد پروژه دکمهٔ **Connect** را بزنید. یک رشته شبیه
   `postgresql://USER:PASSWORD@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require` نشان می‌دهد ← **Copy**.
   این رشته رمز دیتابیس است: جایی منتشرش نکنید، فقط در قدم ۴ در GitHub بگذارید.
4. (افزونهٔ pgvector را لازم نیست دستی فعال کنید؛ دستور `migrate` خودش فعالش می‌کند.)

**۳. کلید رایگان Gemini** — [aistudio.google.com/apikey](https://aistudio.google.com/apikey) ← **Create API key** ← کپی.
بدون آن، خبرهای RSS منتشر نمی‌شوند (فقط پست‌های کانال منبع می‌روند).

**۴. Secretها در GitHub** — صفحهٔ مخزن ← **Settings** ← منوی کنار: **Secrets and variables** ← **Actions** ←
زبانهٔ **Secrets** ← **New repository secret**. سه بار، هر بار یک نام و یک مقدار:

| Name (دقیقاً همین) | Secret (مقدار) |
|---|---|
| `WANGER_NEWS_BOT_TOKEN` | توکن ربات از BotFather، فقط خودش: `123456789:AA…` (بدون فاصله، بدون «bot» اول آن) |
| `WANGER_NEWS_DATABASE_URL` | رشتهٔ کپی‌شده از Neon در قدم ۲ |
| `WANGER_NEWS_GEMINI_API_KEY` | کلید قدم ۳ |

(اختیاری، زبانهٔ **Variables**: `WANGER_NEWS_ADMIN_IDS` = شناسهٔ عددی ادمین‌های دیگر با کاما.)

**۵. اجرای اول** — زبانهٔ **Actions** ← **Wanger News** ← **Run workflow** ← از فهرست به ترتیب:
`migrate` (ساخت جدول‌ها) ← `doctor` (توکن، کلید، کانال‌ها و ادمین بودن ربات را بررسی می‌کند؛ اگر ✖ داشت، همان را
درست کنید) ← `run-once`. برای اجرای خودکار منظم، قدم ۷ را انجام دهید.

**۶. پنل** — به ربات `/start` بدهید. در اجرای بعدی (حدود ۱۰ دقیقه) پنل مدیریت با دکمه می‌آید.

**۷. اجرای منظم هر ۱۰ دقیقه (زمان‌سنج بیرونی رایگان)** — زمان‌بندی خود GitHub برای این مخزن ساعت‌ها دیر
می‌کند. پس سایت رایگان [cron-job.org](https://cron-job.org) هر ۱۰ دقیقه به GitHub می‌گوید «یک بار اجرا کن»
(ADR-053). زمان‌بندی GitHub ساعتی به‌عنوان پشتیبان می‌ماند.

*الف) یک توکن محدود در GitHub* (فقط اجازهٔ «اجرای workflow در همین مخزن»):
1. GitHub ← عکس پروفایل (بالا راست) ← **Settings** ← پایین منوی کنار: **Developer settings** ←
   **Personal access tokens** ← **Fine-grained tokens** ← **Generate new token**.
2. **Token name**: `wanger-news-timer` · **Expiration**: مثلاً ۹۰ روز یا یک سال (تاریخش را یادداشت کنید؛ بعد از
   انقضا ربات خودکار اجرا نمی‌شود و باید توکن تازه بسازید و در cron-job.org عوض کنید).
3. **Repository access** ← **Only select repositories** ← فقط `imkiimiw/Kimia`.
4. **Permissions** ← **Repository permissions** ← **Actions** ← **Read and write**. (Metadata خودش Read-only
   می‌شود.) هیچ اجازهٔ دیگری لازم نیست.
5. **Generate token** ← توکن (`github_pat_…`) را کپی کنید. فقط یک بار نشان داده می‌شود؛ جایی منتشرش نکنید.

*ب) job در cron-job.org*:
1. در [cron-job.org](https://cron-job.org) ثبت‌نام کنید ← **Create cronjob**.
2. **Title**: `Wanger News` · **URL**:
   `https://api.github.com/repos/imkiimiw/Kimia/actions/workflows/news.yml/dispatches`
3. **Execution schedule**: **Every 10 minutes**.
4. زبانهٔ **Advanced**: **Request method** = `POST`. در **Headers** این چهار سطر (Key / Value):

   | Key | Value |
   |---|---|
   | `Authorization` | `Bearer ` + توکن قدم الف (یک فاصله بعد از Bearer) |
   | `Accept` | `application/vnd.github+json` |
   | `X-GitHub-Api-Version` | `2022-11-28` |
   | `Content-Type` | `application/json` |

   **Request body**:
   ```json
   {"ref":"claude/todo-bot-mandatory-channels-h9wcew","inputs":{"command":"run-once","trigger":"cron"}}
   ```
5. **Create** ← دکمهٔ **Test run**: پاسخ درست `204 No Content` است و در زبانهٔ Actions یک اجرای تازهٔ
   «Wanger News» دیده می‌شود. `401` = توکن اشتباه یا منقضی؛ `403`/`404` = اجازهٔ Actions یا مخزن درست انتخاب
   نشده؛ `422` = اسم branch یا ورودی‌ها اشتباه است.

> توکن پیش cron-job.org می‌ماند. با این اجازه‌ها فقط می‌تواند workflowهای همین مخزن را اجرا کند (نه کد را
> عوض کند، نه Secretها را بخواند). اگر شک کردید، در همان صفحهٔ Fine-grained tokens حذفش کنید.

> ربات سرور همیشه‌روشن ندارد: پیام‌ها و دکمه‌ها در هر اجرا (هر ۱۰ دقیقه) خوانده می‌شوند، پس پاسخ با تأخیر
> می‌آید. اگر مخزن ۶۰ روز فعالیتی نداشته باشد، GitHub زمان‌بندی خودش را خاموش می‌کند (زمان‌سنج بیرونی را نه).
> تلگرام update‌ها را فقط ۲۴ ساعت نگه می‌دارد.

**سهمیهٔ هوش مصنوعی برای کل ماه** — سهمیهٔ رایگان Gemini روزانه است. ربات آن را یکنواخت در طول روز خرج می‌کند
(هر اجرا فقط سهم همان بازه را)، پس هیچ روزی سهمیه صبح تمام نمی‌شود و هر روزِ ماه خلاصه ساخته می‌شود (ADR-052).
پیش‌فرض ۱۵۰ درخواست در روز است. عدد واقعی پروژهٔ شما در [AI Studio](https://aistudio.google.com) ← **Rate
limits** ← ستون **RPD** مدل `gemini-3.5-flash-lite` است؛ آن را به ربات بدهید: `/quota 1000` (عدد خودتان). اگر
گوگل عدد کمتری اعلام کند، ربات خودش همان را جایگزین می‌کند. `/quota` بدون عدد وضعیت را نشان می‌دهد.

## پنل مدیریت داخل ربات (`/panel`، فقط مالک)

| دکمه | کار |
|---|---|
| 📊 وضعیت | نسخه، مقصد، سهمیهٔ AI، صف‌ها، منابع خراب، خطاها |
| 📡 کانال‌ها | عوض کردن کانال تست و اصلی، افزودن/حذف کانال منبع، «انتشار در کانال اصلی/تست». ربات قبل از ذخیره چک می‌کند که کانال باشد و ربات در آن ادمین (با اجازهٔ پست) باشد. کانال تست/اصلی نمی‌تواند منبع هم باشد |
| 📰 منابع خبری | روشن/خاموش کردن هر منبع RSS (۸ تا در هر صفحه). 🔒 = به دلیل حقوقی یا فنی خاموش (paywall، مجوز، فید خراب) و از ربات روشن نمی‌شود |
| ⚙️ حالت انتشار | خودکار / نیمه‌خودکار / دستی برای پیش‌فرض و برای هر دسته |
| ⏸ توقف / ▶️ ادامه | توقف و ادامهٔ انتشار (جمع‌آوری ادامه دارد) |
| 🧐 منتظر بررسی · 📈 روندها · 🗞 خلاصهٔ روز | همان `/pending`، `/trends`، `/brief` |

دستور متنی هم هست: `/channel test @نام` · `/channel main @نام` · `/channel source add @نام` ·
`/channel source remove @نام` · `/channel target test|main`. تغییرات از اجرای بعدی اعمال می‌شوند و در دیتابیس
می‌مانند (بر تنظیمات GitHub مقدم‌اند).

## پست‌های کانال منبع

هر پستی در کانال منبع بگذارید، اگر قبلاً منتشر نشده باشد، در کانال مقصد **دوباره فرستاده می‌شود** (نه فوروارد):
آیدی‌های تلگرامی متن (‎@نام، لینک‌های t.me و خط‌هایی مثل «🆔 ‎@channel» یا «عضو شوید: …») حذف می‌شوند، قالب‌بندی
متن (بولد، لینک سایت‌ها) و عکس/ویدیو/آلبوم حفظ می‌شود، و در پایان می‌آید:

```
✍️ #اسم_پست‌گذار     ← امضای کانال منبع (Sign Messages باید روشن باشد)
🆔 @maghsad98        ← آیدی کانالی که پست در آن منتشر می‌شود
```

برای کپی بدون تغییر (رفتار قدیم): `telegram.source_posts.mode: copy` در `config/pipeline.yaml`.

## اجرای محلی

```bash
cd wanger-news
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -e ".[dev]"
cp .env.example .env            # و مقدارها را پر کنید
.venv/bin/python -m wanger_news validate-config
.venv/bin/python -m wanger_news run-once --dry-run   # بدون دیتابیس هم کار می‌کند؛ هیچ چیز ارسال نمی‌شود
.venv/bin/python -m wanger_news migrate
.venv/bin/python -m wanger_news doctor
.venv/bin/python -m wanger_news run-once
```

| دستور | کار |
|---|---|
| `run-once [--dry-run] [--max-posts N] [--source ID] [--no-telegram]` | یک دور کامل |
| `worker [--interval S]` | اجرای پیوسته (گزینهٔ B) |
| `check-sources [--all] [--markdown]` | تست زندهٔ فیدها و robots.txt |
| `migrate [upgrade\|downgrade] [rev]` · `db-check` | مایگریشن‌ها |
| `doctor` · `validate-config` | بررسی تنظیمات |

گزینهٔ B (سرور): `docker compose up -d` (postgres + migrate + worker).
