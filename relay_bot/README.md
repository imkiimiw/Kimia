# 📨 ربات پیام‌رسان (فوروارد + کپی) — فقط روی Telegram Serverless

ربات «تماس با مدیر» که فقط روی **سرورلس خود تلگرام**
([Telegram Serverless](https://core.telegram.org/bots/serverless)) اجرا می‌شود؛ کد، دیتابیس و وبهوک همه داخل
تلگرام است. بدون سرور، VPS یا هاست. لینک شخصی برای کاربرها ندارد: هر کسی ربات را استارت کند می‌تواند پیام بدهد.

این پوشه یک پروژه‌ی **جدا** است. ربات‌های دیگر مخزن (تودو در ریشه، نجوا در `whisper_bot/`) دست نخورده‌اند.

## چه می‌کند

هر پیامی که کاربری به ربات بدهد (متن، عکس، ویدیو، ویس، فایل، استیکر، لوکیشن، …)، برای مالک **سه پیام** می‌آید:

1. **«📩 پیام جدید»**: نام فرستنده (با لمس آن پروفایلش باز می‌شود)، یوزرنیم و آیدی عددی، با دکمه‌ها:
   - **👁 سین بزن**: به فرستنده پیام «👁 پیامت دیده شد.» می‌رود (ریپلای روی پیام خودش). دکمه «✅ سین زده شد» می‌شود؛
     دو بار زدن، دو بار خبر نمی‌دهد.
   - **✉️ پیام بده**: ربات می‌گوید «✍️ پیامت برای … را بفرست» و کادر جواب باز می‌شود. هر چه بفرستید (متن، عکس،
     ویس، فایل، …) برای فرستنده می‌رود، به‌صورت ریپلای روی پیام خودش. اگر پشیمان شدید، کافی است چیزی نفرستید.
   - **⛔️ بلاک**: دیگر پیامش به شما نمی‌رسد (خودش «⛔️ امکان ارسال پیام برای شما وجود ندارد.» می‌گیرد).
     دکمه «✅ آنبلاک» می‌شود.
2. همان پیام، **یک بار فوروارد**‌شده.
3. همان پیام، **یک بار کپی**‌شده.

- فرستنده بعد از هر پیام «✅ پیامت ارسال شد.» می‌گیرد. برای آلبوم فقط یک «📩 پیام جدید (آلبوم)» و یک «✅» می‌آید.
- روی هر کدام از این سه پیام **Reply** هم بزنید، جوابتان برای فرستنده می‌رود. با Reply و نوشتن `/block` یا
  `/unblock` هم می‌شود بلاک کرد.
- **مالک فقط آیدی عددی `5557901897`** است (در `tgcloud/lib/config.js`). پیام‌های خود مالک فوروارد نمی‌شوند؛ برای
  امتحان از یک **حساب دوم** پیام بدهید. مالک باید یک بار ربات را `/start` کرده باشد.

## 🚀 راه‌اندازی با CLI (روشی که الان روی ربات اجرا شده)

با Node.js ۱۸ به بالا، **داخل همین پوشه**:

```bash
cd relay_bot
npm install
mkdir -p .tgcloud              # مهم: وگرنه CLI ممکن است پروژه‌ی ریشه‌ی مخزن را بردارد
npx tgcloud login              # یا متغیر TGCLOUD_TOKEN (BotFather ← ربات ← Serverless ← CLI Access)
npx tgcloud status             # باید فقط همین ۵ ماژول را نشان دهد
npx tgcloud push               # آپلود کد (ماژول‌هایی که در cloud هستند و اینجا نیستند پاک می‌شوند)
npx tgcloud migrate --safe     # ساخت جدول‌های users و links
npx tgcloud webhook            # باید in sync باشد و message و callback_query را داشته باشد
npm run test:cloud             # تست روی خود سرورلس (پیام‌های آزمایشی آخرش پاک می‌شوند)
```

> پشت پروکسی HTTPS (مثلاً نشست ابری Claude Code) دستورهای CLI را با `NODE_USE_ENV_PROXY=1` اجرا کنید؛
> `npm run test:cloud` خودش این کار را می‌کند.

### چسباندن در BotFather (اگر CLI ندارید)

BotFather ← ربات ← Serverless، به همین ترتیب و با **همین نام‌ها** (حروف کوچک؛ `Config` یا `reply` کار نمی‌کند):

| # | بخش | نام | فایل |
|---|---|---|---|
| 1 | Database | — | `tgcloud/schema.js` ← بعد از Save، «**Start Migration**» (۲ جدول: `users`، `links`) |
| 2 | Library | `config` | `tgcloud/lib/config.js` |
| 3 | Library | `relay` | `tgcloud/lib/relay.js` |
| 4 | Handlers | `message` | `tgcloud/handlers/message.js` |
| 5 | Handlers | `callback_query` | `tgcloud/handlers/callback_query.js` |

در کد فقط کامنت `/* */` هست، پس اگر موقع چسباندن خط‌ها به هم بچسبند هم درست کار می‌کند (قبلاً schema.js با
کامنت‌های `//` به همین دلیل کلاً کامنت شده بود و دیتابیس ساخته نشد). بعد از چسباندن به ربات `/start` بدهید؛ خط آخر
راهنما باید «دیتابیس: ✅ آماده» باشد.

## 🧪 تست

| دستور | چه می‌کند |
|---|---|
| `npm test` | بررسی ایستا (import ها، globals ممنوع در V8، نبودن کامنت `//`، سالم ماندن کد بدون خط‌جدید) + **۲۳ سناریو** روی شبیه‌ساز محلی sdk و یک Bot API ساختگی سخت‌گیر |
| `npm run test:cloud` | **۷ بررسی روی خود سرورلس تلگرام** با `npx tgcloud run` (کد محلی، دیتابیس و Bot API واقعی؛ چیزی deploy نمی‌شود) |

`test:cloud` با یک کاربر ساختگی (`990000001`) کار می‌کند که «پیام‌هایش» پیام‌های خود ربات در چت مالک‌اند؛ پس مالک
چند پیام آزمایشی می‌بیند که آخر کار پاک می‌شوند، همراه با ردیف‌های آن کاربر در دیتابیس. رسیدن جواب/«سین» به یک
کاربر واقعی را `npm test` پوشش می‌دهد (در سرورلس، «سین» یک بار برای خود مالک فرستاده و بررسی می‌شود).

## ✅ تست دستی در تلگرام (۲ دقیقه)

با حساب مالک (M) و یک حساب دیگر (A):
1. A: `/start` و بعد یک متن ← A «✅ پیامت ارسال شد.»؛ M سه پیام: «📩 پیام جدید» با دکمه‌ها، فوروارد، کپی.
2. M: «👁 سین بزن» ← A «👁 پیامت دیده شد.» می‌گیرد؛ دکمه «✅ سین زده شد» می‌شود.
3. M: «✉️ پیام بده» ← یک ویس یا متن بفرستد ← A همان را به‌صورت ریپلای روی پیام خودش می‌گیرد.
4. M روی پیام کپی‌شده Reply بزند و عکس بفرستد ← A عکس را می‌گیرد.
5. M: «⛔️ بلاک» ← پیام بعدی A دیگر نمی‌رسد؛ «✅ آنبلاک» ← دوباره می‌رسد.

## نکته‌ها

- آلبوم به‌صورت چند آپدیت جدا می‌رسد، پس عکس‌ها جدا جدا (فوروارد، کپی، …) می‌آیند؛ «📩 پیام جدید» فقط یکی.
- ویرایش پیام (edit) دوباره فرستاده نمی‌شود.
- تلگرام برای هر چت حدود ۱ پیام در ثانیه اجازه می‌دهد؛ اگر خیلی سریع پیام بیاید ممکن است یکی از نسخه‌ها نرسد.
  کاربر فقط وقتی «❌ ارسال نشد» می‌گیرد که نه فوروارد رسیده باشد نه کپی.
- برخی پیام‌ها کپی‌شدنی نیستند (مثلاً نظرسنجی کوییز)؛ به‌جای کپی یک «⚠️ کپی ممکن نشد» می‌آید که روی آن هم
  می‌شود Reply زد.

## 🏗 ساختار

```
tgcloud/
  schema.js                  جدول‌های users (نام و بلاک) و links (هر پیام در چت مالک مال کدام کاربر است، و «سین»)
  lib/config.js              آیدی عددی مالک
  lib/relay.js               همه‌ی منطق ربات (ترتیب کارها و callback_data ها در توضیح بالای فایل)
  handlers/message.js        پیام‌ها
  handlers/callback_query.js دکمه‌های «📩 پیام جدید»
test/
  e2e.mjs, static.mjs        تست‌های محلی (test/sdk = شبیه‌ساز sdk، mock-telegram.mjs = شبیه‌ساز Bot API)
  cloud/run.mjs              تست روی خود سرورلس؛ cloud/devtools.js فقط در طول اجرای آن (هرگز push نشود)
```
