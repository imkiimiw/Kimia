# 📨 ربات پیام‌رسان (فوروارد + کپی) — فقط روی Telegram Serverless

ربات «تماس با مدیر» که فقط روی **سرورلس خود تلگرام**
([Telegram Serverless](https://core.telegram.org/bots/serverless)) اجرا می‌شود؛ کد، دیتابیس و وبهوک همه داخل
تلگرام است. بدون سرور، VPS یا هاست.

این پوشه یک پروژه‌ی **جدا** است (ربات جدید). ربات‌های دیگر مخزن (تودو در ریشه، نجوا در `whisper_bot/`) دست نخورده‌اند.

## چه می‌کند

1. **هر پیامی** که کاربری به ربات بدهد (متن، عکس، ویدیو، ویس، فایل، استیکر، لوکیشن، …) برای مالک
   **یک بار فوروارد** و **یک بار کپی** می‌شود. زیر پیام کپی‌شده دو دکمه هست:
   «👤 نام · @یوزرنیم» (اطلاعات کاربر: آیدی، تعداد پیام، تاریخ اولین پیام، وضعیت) و «⛔️ مسدود کردن».
2. کاربر بعد از هر پیام «✅ پیامت ارسال شد.» می‌گیرد (برای آلبوم فقط یک بار).
3. **مالک جواب می‌دهد**: روی پیام فورواردشده **یا** کپی‌شده **Reply** بزنید و هر چیزی بفرستید (متن، عکس، ویس، فایل،
   استیکر، …). همان پیام برای کاربر می‌رود، به‌صورت ریپلای روی پیام خودش. شما «✅ برای فلانی ارسال شد.» می‌گیرید.
4. **مسدود کردن**: دکمه‌ی «⛔️ مسدود کردن» زیر پیام کپی‌شده (یا Reply روی پیام کاربر و نوشتن `/block`). پیام‌های
   کاربر مسدود دیگر به شما نمی‌رسد. رفع مسدودی: دکمه‌ی «✅ رفع مسدودی» یا Reply و `/unblock`.

- **مالک فقط آیدی عددی `5557901897`** است (در `tgcloud/lib/config.js`). اگر آیدی شما فرق دارد، همان‌جا عوضش کنید
  (آیدی خودتان را از [@userinfobot](https://t.me/userinfobot) بگیرید).
- پیام‌های خود مالک هیچ‌وقت فوروارد نمی‌شوند؛ برای امتحان از یک **حساب دوم** پیام بدهید.
- اگر کاربر در تنظیمات حریم خصوصی «فوروارد» را بسته باشد، روی پیام فورواردشده اسمش لینک ندارد؛ ولی جواب دادن با
  Reply روی همان پیام هم کار می‌کند (ربات در دیتابیس نگه می‌دارد هر پیام مال کیست).

## 🚀 راه‌اندازی با چسباندن کد در BotFather (بدون CLI)

[@BotFather](https://t.me/BotFather) ← ربات ← **Serverless** ← روشن. بعد هر فایل را **به همین ترتیب** بچسبانید و
Save کنید (هر فایل فقط فایل‌های قبل از خودش را import می‌کند):

| # | بخش در BotFather | نام | فایل |
|---|---|---|---|
| 1 | Database | — | `tgcloud/schema.js` ← بعد از Save، در Migration «**Start Migration**» (۲ جدول: `users`، `links`) |
| 2 | Library | `config` | `tgcloud/lib/config.js` |
| 3 | Library | `relay` | `tgcloud/lib/relay.js` |
| 4 | Handlers | `message` | `tgcloud/handlers/message.js` |
| 5 | Handlers | `callback_query` | `tgcloud/handlers/callback_query.js` |

سپس **با حساب مالک به ربات `/start` بدهید** (لازم است؛ تا مالک ربات را استارت نکند تلگرام اجازه نمی‌دهد ربات به او
پیام بدهد). راهنمای مالک می‌آید و خط آخرش باید «دیتابیس: ✅ آماده» باشد. اگر «❌» بود، Migration را اجرا کنید.
(تا آن موقع هم ربات پیام‌ها را می‌رساند و Reply روی پیام کپی‌شده کار می‌کند؛ فقط مسدود کردن کار نمی‌کند.)

## روش ۲: با CLI رسمی

با Node.js ۱۸ به بالا، **داخل همین پوشه**:

```bash
cd relay_bot
npm install
mkdir -p .tgcloud              # مهم: وگرنه CLI ممکن است پروژه‌ی ریشه‌ی مخزن را بردارد
npx tgcloud login              # توکن: BotFather ← ربات ← Serverless ← CLI Access ← Access token
npx tgcloud status             # باید فقط همین ۵ ماژول را نشان دهد
npx tgcloud push
npx tgcloud migrate --safe     # ساخت جدول‌های users و links
npx tgcloud webhook            # باید in sync باشد و message و callback_query را داشته باشد
# امتحان روی خود سرورلس: راهنمای مالک را برایتان می‌فرستد
npx tgcloud run handlers/message '{ message_id: 1, from: { id: 5557901897, is_bot: false, first_name: "Owner" }, chat: { id: 5557901897, type: "private" }, date: 0, text: "/start" }'
```

## ✅ تست دستی در تلگرام (۲ دقیقه)

با حساب مالک (M) و یک حساب دیگر (A):
1. M: `/start` ← راهنما با «دیتابیس: ✅ آماده».
2. A: `/start` ← خوش‌آمد. A یک متن بفرستد ← A «✅ پیامت ارسال شد.» می‌گیرد؛ M دو پیام می‌گیرد: فوروارد و کپی (با دکمه‌ها).
3. M روی **فوروارد** Reply بزند و متن بفرستد ← A جواب را به‌صورت ریپلای روی پیام خودش می‌گیرد؛ M «✅ برای … ارسال شد.»
4. M روی **کپی** Reply بزند و یک ویس یا عکس بفرستد ← A همان را می‌گیرد.
5. A یک آلبوم ۳ عکسی بفرستد ← M سه فوروارد و سه کپی می‌گیرد؛ A فقط یک «✅».
6. M دکمه‌ی «👤 …» را بزند ← پنجره‌ی اطلاعات A. دکمه‌ی «⛔️ مسدود کردن» ← دکمه «✅ رفع مسدودی» می‌شود؛ پیام بعدی A دیگر
   به M نمی‌رسد و A «⛔️ امکان ارسال پیام برای شما وجود ندارد.» می‌گیرد. «✅ رفع مسدودی» ← دوباره کار می‌کند.
7. M بدون Reply چیزی بفرستد ← فقط راهنمای «Reply بزن»؛ به هیچ کاربری چیزی نمی‌رود.

## 🧪 تست خودکار

```bash
npm test
```

بررسی ایستا (import ها، globals ممنوع در V8 سرورلس، ساختار پوشه‌ها) + **۲۳ سناریو**: کد واقعی handler ها روی
شبیه‌ساز محلی `sdk` (دیتابیس SQLite واقعی) و یک Bot API ساختگیِ سخت‌گیر اجرا می‌شود که پیام‌های هر چت را نگه می‌دارد و
هر چیزی را که تلگرام رد می‌کند رد می‌کند. سناریوها: فوروارد + کپی برای هر نوع پیام، جواب مالک روی فوروارد و روی کپی
(متن، ویس، عکس، استیکر، …)، کاربری که فوروارد را بسته، آلبوم‌ها (همزمان) در هر دو جهت، پیام غیرقابل کپی (کوییز)،
پیام‌های سرویس و گروه، مالکی که ربات را استارت نکرده، کاربری که ربات را بلاک کرده، دکمه‌ها (اطلاعات، مسدود، رفع مسدودی،
فشردن توسط غیرمالک)، `/block` و `/unblock`، escape شدن HTML در اسم‌ها، و کار کردن ربات وقتی Migration اجرا نشده.

## نکته‌ها

- آلبوم در تلگرام به‌صورت چند آپدیت جدا می‌رسد، پس عکس‌ها جدا جدا (فوروارد، کپی، فوروارد، کپی، …) برای مالک می‌آیند.
- ویرایش پیام (edit) دوباره فرستاده نمی‌شود.
- تلگرام برای هر چت حدود ۱ پیام در ثانیه اجازه می‌دهد؛ اگر کاربرها خیلی سریع پیام بدهند ممکن است یکی از دو نسخه
  (فوروارد یا کپی) نرسد. کاربر فقط وقتی «❌ ارسال نشد» می‌گیرد که هیچ‌کدام نرسیده باشد.
- برخی پیام‌ها کپی‌شدنی نیستند (مثلاً نظرسنجی کوییز)؛ آن‌وقت به‌جای کپی یک پیام «⚠️ کپی ممکن نشد» با همان دکمه‌ها
  می‌آید که روی آن هم می‌شود Reply زد.

## 🏗 ساختار

```
tgcloud/
  schema.js                  جدول‌های users (کاربران و مسدودی) و links (هر پیام در چت مالک مال کدام کاربر است)
  lib/config.js              آیدی عددی مالک
  lib/relay.js               همه‌ی منطق ربات (ترتیب کارها و callback_data ها در توضیح بالای فایل)
  handlers/message.js        پیام‌ها
  handlers/callback_query.js دکمه‌های زیر پیام کپی‌شده
test/
  e2e.mjs, static.mjs        تست‌ها (test/sdk = شبیه‌ساز sdk، mock-telegram.mjs = شبیه‌ساز Bot API)
```
