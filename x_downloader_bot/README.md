# 📥 ربات دانلود رسانه از X (توییتر) — فقط روی Telegram Serverless

ربات فارسی که ویدیو، عکس و گیف پست‌های X را می‌فرستد، با **عضویت اجباری** و **پنل مالک**. فقط روی
سرورلس خود تلگرام ([Telegram Serverless](https://core.telegram.org/bots/serverless)) اجرا می‌شود: کد،
دیتابیس و وبهوک همه داخل تلگرام است. بدون VPS، Vercel، Cloudflare، AWS یا GitHub Actions.

## ✨ ۱۰ قابلیت

| # | قابلیت | توضیح |
|---|---|---|
| 1 | 🎬 دانلود ویدیو | لینک پست را بفرستید؛ ویدیو با `sendVideo` می‌آید |
| 2 | 🔽 کیفیت خودکار | بهترین mp4 که در سقف‌ها جا شود؛ اگر کمترین کیفیت هم بیشتر از ۵۰ مگابایت باشد، توضیح + لینک مستقیم |
| 3 | 🎚 انتخاب کیفیت | تنظیمات: خودکار (تا ۷۲۰p) / بهترین / کم‌حجم؛ و دکمه‌ی «کیفیت‌های دیگر» زیر هر ویدیو |
| 4 | 🖼 عکس‌ها | چند عکس = یک آلبوم (`sendMediaGroup`) با اندازه‌ی اصلی (`name=orig`)؛ دکمه‌ی «فایل اصلی» بدون فشرده‌سازی |
| 5 | 🎞 گیف | با `sendAnimation`، نه ویدیوی معمولی |
| 6 | 📝 کپشن | روشن/خاموش: متن پست، نویسنده (@username)، لینک اصلی؛ همیشه زیر ۱۰۲۴ کاراکتر |
| 7 | ⚡️ کش | `file_id` هر پست و هر کیفیت ذخیره می‌شود؛ درخواست تکراری بدون دانلود و فوری |
| 8 | 🔗 چند لینک | تا ۵ لینک در یک پیام، یکی‌یکی، با پیام پیشرفت و خلاصه‌ی نتیجه |
| 9 | 📊 سهمیه | ۳۰ پست در روز برای هر کاربر (مالک نامحدود)، و ۵ ثانیه فاصله بین درخواست‌ها |
| 10 | 📜 تاریخچه و پروفایل | ۲۰ دانلود آخر با دکمه‌ی ارسال دوباره از کش؛ آمار شخصی (امروز، کل، باقی‌مانده) |

لینک‌های قابل قبول: `x.com`، `twitter.com`، `mobile.twitter.com`، `fxtwitter.com`، `fixupx.com`، `vxtwitter.com`،
`fixvx.com` (با `/user/status/ID`، `/i/status/ID` یا `/i/web/status/ID`)؛ `?s=20&t=…` و هر پارامتر دیگری نادیده گرفته می‌شود.

## 🌐 منبع رسانه

- اصلی: [FxTwitter](https://api.fxtwitter.com) — `api.fxtwitter.com/{user}/status/{id}` و `tweet.media`.
- جایگزین: [vxTwitter](https://api.vxtwitter.com) — فقط اگر FxTwitter خطا بدهد یا رسانه برنگرداند.
- هر API در خطای موقت **یک بار دوباره** امتحان می‌شود. همه‌ی منطق در `tgcloud/lib/x_api.js` است.
- رسانه **فقط** از `video.twimg.com` و `pbs.twimg.com` دانلود می‌شود (محافظت SSRF).
- `fetch` سرورلس هر پاسخ را به ۳۰ مگابایت محدود می‌کند، پس فایل‌های بزرگ‌تر (تا ۵۰ مگابایتِ آپلود ربات)
  در چند تکه‌ی Range دانلود می‌شوند.

## 🔒 عضویت اجباری و 👑 پنل مالک

- مالک **فقط آیدی عددی `5557901897`** است؛ هر دستور و دکمه‌ی مدیریتی سمت سرور با `from.id` بررسی می‌شود.
- کانال‌های اولیه (فقط اگر جدول خالی باشد): `@HIDE_i_SEEK`، `@Nepenthw_ir`، `@wangerBots`.
- عضو = `member` / `administrator` / `creator`، یا `restricted` با `is_member: true`.
- اگر بررسی یک کانال خطا بدهد (مثلاً ربات ادمین نیست)، آن کانال برای کاربران نادیده گرفته می‌شود و به مالک
  حداکثر هر ۳ ساعت یک‌بار هشدار داده می‌شود.
- `/admin` (فقط مالک، فقط پی‌وی): لیست/افزودن/حذف کانال (سقف ۱۰، بررسی با `getChat` و `getChatMember`)،
  روشن/خاموش عضویت اجباری، مسدود/رفع مسدودی با آیدی عددی، آمار (کاربران، فعال‌ها، دانلود امروز و کل،
  خطاهای API امروز)، و **📢 پیام سراسری**.
- پیام سراسری: هر نوع پیام (متن، عکس، ویدیو، فایل، با کپشن) با پیش‌نمایش و تأیید، با `copyMessage`. چون
  سرورلس زمان‌بند ندارد، یک صف در دیتابیس است: هر «▶️ ادامه ارسال» ۲۵ نفر، و با هر پیام دیگری که به ربات
  برسد ۵ نفر دیگر. ۴۰۳ = کاربر غیرفعال و دیگر تکرار نمی‌شود؛ ۴۲۹ = توقف دسته تا `retry_after`؛ بقیه = ناموفق.

## 🚀 راه‌اندازی

پیش‌نیاز در تلگرام:
1. [@BotFather](https://t.me/BotFather) ← ربات ← **Serverless** ← روشن.
2. ربات را در هر سه کانال **ادمین** کنید (بدون ادمین بودن، تلگرام اجازه‌ی بررسی عضویت نمی‌دهد).

با Node.js ۱۸ به بالا، در پوشه‌ی `x_downloader_bot`:

1. توکن CLI را بگیرید: BotFather ← ربات ← Serverless ← CLI Access ← Access token (شکلش `app<id>:<secret>` است،
   نه توکن خود ربات).
2. آن را در متغیر **`X_BOT_TGCLOUD_TOKEN`** بگذارید: در تنظیمات محیط (Environment variables)، یا در
   فایل `x_downloader_bot/.env` (از روی `.env.example`؛ این فایل در git نمی‌رود). اسم جدا برای هر ربات باعث
   می‌شود هیچ‌وقت کد این ربات روی ربات دیگری در همین مخزن push نشود.
3. دستورها (همه از طریق `scripts/tg.mjs`، که توکن را فقط به همان پردازش CLI می‌دهد):

```bash
npm install
npm run tg -- status && npm run tg -- diff
npm run tg -- push
npm run tg -- migrate --dry-run
npm run tg -- migrate --safe   # ۱۰ جدول
npm run tg -- webhook          # باید in sync باشد؛ وگرنه: npm run tg -- webhook sync
npm run deploy                 # بعدها: migrate --local --safe ← push ← migrate --safe ← webhook
```

## 🧪 تست

```bash
npm test                  # تست واحد + ۳۱ سناریوی سرتاسری روی شبیه‌ساز محلی (با پاسخ‌های واقعی ضبط‌شده)
npm run test:live         # سناریوهای دانلود با FxTwitter / vxTwitter / twimg واقعی (فقط تلگرام شبیه‌سازی‌شده)
npm run test:cloud        # همه‌ی سناریوها روی خود Telegram Serverless با `npx tgcloud run`
npm run test:cloud:local  # بررسی خود اسکریپت تست ابری روی شبیه‌ساز
```

`test:cloud` روی دیتابیس واقعی اجرا می‌شود: دانلودها به **چت مالک** فرستاده می‌شوند (پس در تلگرام دیده
می‌شوند)، کاربران آزمایشی آیدی‌های `990000001` تا `990000003` دارند و همه چیز در پایان برمی‌گردد. تست پیام
سراسری فقط وقتی اجرا می‌شود که ربات هیچ کاربر واقعی جز مالک نداشته باشد.

## 🏗 ساختار

```
tgcloud/
  schema.js                  ۱۰ جدول (بدون کلید خارجی؛ شناسه‌ی پست‌ها TEXT چون از 2^53 بزرگ‌ترند)
  handlers/message.js        پیام‌ها
  handlers/callback_query.js دکمه‌ها (هر دکمه دقیقاً یک answerCallbackQuery)
  lib/
    router.js    ترتیب بررسی‌ها و جدول کدهای callback_data
    x_api.js     FxTwitter + vxTwitter (همه‌ی منطق API)
    media.js     اندازه، دانلود (Range)، انتخاب کیفیت
    deliver.js   ارسال پست: کش، آلبوم، گیف، کپشن، لینک مستقیم
    features.js  لینک‌ها، سهمیه، کیفیت، تاریخچه، پروفایل، تنظیمات
    admin.js     پنل مالک: کانال‌ها، مسدودی، آمار
    broadcast.js پیام سراسری (صف در دیتابیس)
    join.js      عضویت اجباری
    store.js     همه‌ی کوئری‌های دیتابیس
    links.js, tg.js, ui.js, text.js, config.js
test/
  unit.mjs, e2e.mjs, live.mjs   تست‌های محلی (sdk/ = شبیه‌ساز sdk، fixtures/ = پاسخ‌های واقعی API)
  cloud/run-tests.mjs           تست روی خود سرورلس تلگرام
```
